# LumaGlass Studio by EVEL

**Copyright © 2026 EVEL. All rights reserved for the original project code, interface design, and visual identity.** See `COPYRIGHT.md` for third-party notices and limitations.

LumaGlass Studio is a responsive Arabic RTL media workspace with a liquid-glass interface. It is served by FastAPI and uses a Redis/RQ worker queue for larger media tasks. FFmpeg handles media encoding; Pillow handles image conversion and conventional sharpness enhancement. Optional Cloudflare R2-compatible storage can keep finished files off local disk.

## Current tools

- Video compression with quality presets and optional resolution limits.
- Conversion between common video/audio formats (MP4, WebM, MKV, MOV, MP3, M4A, WAV, OGG, FLAC).
- Audio extraction, a single-frame export, and trimming a video clip.
- Image conversion and optional maximum width (WebP, JPEG, PNG).
- Conventional image/video upscaling and sharpness enhancement. **This is not AI restoration**; Real-ESRGAN/GPU model inference is not bundled in this version.
- Task queue, progress reporting, recent-task history during the current page session, and scheduled cleanup of temporary files.
- Optional direct-file URL imports restricted to an explicit HTTPS hostname allowlist. Social-media post pages and redirects are deliberately unsupported.
- Optional API access-key protection and optional R2 result storage with expiring signed download links.

## Render demo deployment

The package root includes `render.yaml` and `media-studio/Dockerfile.render`. See `RENDER_DEPLOYMENT.md` for deployment steps. This profile co-locates Redis, the RQ worker, and FastAPI in a single Docker web service so upload paths are shared. It is for a small demo, not a durable production service: the free-tier filesystem/queue can be lost on restarts or idle spin-down, and resource limits can constrain media jobs.

## Deploy with Docker Compose

1. Copy `.env.example` to `.env` in this directory.
2. Replace `API_ACCESS_TOKEN` with a long, random value. Do not deploy with the sample placeholder. Keep `REQUIRE_API_KEY=true`.
3. Run `docker compose up --build -d` from this directory.
4. Open `http://YOUR-SERVER:8000` locally for a smoke test. For internet access, put the service behind HTTPS and firewall/rate-limit rules.
5. The API and worker share `/data/jobs`. Redis is private to the Compose network; it is not published to the internet.
6. The health endpoint is `/api/health`. It reports whether Redis, FFmpeg, URL import, API-key protection, and R2 are configured; it does not reveal secret values.
7. Open **إعدادات الوصول** at the bottom of the UI, paste the same server API key, and save it in the current browser. The key is stored in that browser's local storage and sent only when creating processing tasks. It is not included in HTML source.

The included `Dockerfile` is the API/worker image. Docker Compose starts Redis, the API process, and a separate RQ worker process.

## Optional R2 result storage

To enable Cloudflare R2 or another S3-compatible target, fill all `R2_*` variables in the server-side `.env`:

- `R2_ENDPOINT_URL`
- `R2_BUCKET`
- `R2_ACCESS_KEY_ID`
- `R2_SECRET_ACCESS_KEY`
- `R2_REGION=auto`
- `R2_PRESIGN_SECONDS=900`

The worker uploads completed output files to `results/` and removes the local output file. Downloads are redirected through a short-lived presigned URL generated by the backend. Credentials never enter the browser. Add a bucket lifecycle rule to expire `results/` objects (for example after one day); signed URLs expiring does not delete the underlying objects. Keep the R2 access key restricted to the necessary bucket actions.

## Optional direct-file URL imports

They are disabled by default. Only enable this for domains you own or are authorized to fetch. Set `ALLOWED_DIRECT_HOSTS` to exact hostnames separated by commas; use HTTPS links to direct media files with supported extensions. Redirects are blocked, hostnames must resolve to public addresses, and uploads/downloads share the configured size limit. URL imports are intentionally not general-purpose social-platform downloaders. DNS rebinding remains a deployment concern, so use outbound network controls/allowlists as an additional defense.

## Production checklist

- Set an unpredictable `API_ACCESS_TOKEN` and retain `REQUIRE_API_KEY=true`.
- Deploy behind HTTPS; expose only the web/API port, never Redis.
- Put a reverse-proxy limit/rate limiter in front of upload endpoints and monitor worker CPU/RAM/disk.
- Review retention and storage lifecycle policies. Local files are cleaned periodically; without R2 they remain temporary on the shared volume until cleanup.
- Ensure your deployed FFmpeg build and all Python dependencies comply with their own licenses.
- Process only content you own or have permission to process. Do not circumvent DRM, authentication barriers, or platform download restrictions.
