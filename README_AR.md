# BuildLab مصر 2.2.0 — مقارنة وتجميع قطع الكمبيوتر مع مستشار AI

دي نسخة ويب جاهزة للنشر على Vercel. البحث والمقارنة وتجميع القطع يشتغلوا مستقلين عن مستشار AI؛ تفعيل المستشار اختياري.

## الموجود في النسخة

- بحث أسعار قطع هاردوير مصرية من مؤشر مقارنة، مع تصنيفات وفرز وعروض المتاجر.
- فحص صفحة المتجر المباشر عند توفر رابط مدعوم، مع إظهار «غير مؤكد» عند تعذر الإثبات.
- مجمّع تجميعة متعدد الخانات، ميزانية، حفظ محلي، تصدير ملخص، وتنبيهات توافق أولية.
- تبويب مستشار BuildLab AI داخل الموقع، يراجع التوافق والاختناقات والبدائل ويرسل سياق التجميعة الحالية مع كل رسالة.
- مزودان فقط: Gemini أساسي وGroq احتياطي. إذا فشل الأول بسبب نفاد الحصة أو عطل أو مشكلة بالموديل/المفتاح، يجرب الخادم الثاني. لو فشل الاثنان تُرد الرسالة إلى حصة المستخدم.
- تسجيل دخول منفصل للمستشار باستخدام Supabase Auth، وحصة يومية محفوظة في Supabase Database لكل حساب. القيمة الافتراضية 10 رسائل يوميًا، قابلة للتعديل من `AI_DAILY_MESSAGE_LIMIT`.

## مزودو الذكاء الاصطناعي

- Gemini: الافتراضي `gemini-3.8-flash`.
- Groq: الافتراضي `openai/gpt-oss-20b`.

الموديلات قابلة للتعديل من متغيرات البيئة `GEMINI_MODEL` و`GROQ_MODEL`. أسماء الموديلات الافتراضية تمت مراجعتها في صفحات المزودين الرسمية بتاريخ 3 نوفمبر 2026. ابقَ على مستوى Groq المجاني؛ الترقية إلى Developer تستخدم الفوترة حسب الاستهلاك وتتطلب وسيلة دفع. كما توضح Google أن بيانات استخدام Gemini ضمن المستوى المجاني قد تُستخدم لتحسين منتجاتها، لذلك لا ترسل معلومات شخصية أو سرية إلى الشات. صفحات الشروط والأسعار قابلة للتغيير:
- Gemini Models: https://ai.google.dev/gemini-api/docs/models
- Groq Supported Models: https://console.groq.com/docs/models

## إعداد Supabase مرة واحدة

لا يوجد تسجيل دخول في النسخة الأساسية القديمة؛ لذلك أُضيف تسجيل الدخول للمستشار فقط حتى لا يمكن للزائر تجاوز حد الرسائل بتغيير عداد المتصفح.

1. أنشئ مشروعًا في Supabase.
2. من **Authentication → URL Configuration** أضف رابط موقع Vercel إلى Site URL وRedirect URLs.
3. اترك تسجيل البريد الإلكتروني وكلمة المرور مفعّلًا. لو تأكيد البريد الإلكتروني مطلوب، المستخدم يؤكد بريده أولًا ثم يسجل الدخول.
4. افتح **SQL Editor** وشغّل كامل الملف `supabase/buildlab-ai-quota.sql` مرة واحدة. ينشئ جدول عداد الرسائل ودالتين ذريتين لحجز الرسالة وإرجاعها عند فشل المزودين.
5. من إعدادات المشروع انسخ Project URL وPublishable key وSecret key.

## متغيرات Vercel

من **Vercel → Project → Settings → Environment Variables** أضف:

| المتغير | القيمة |
|---|---|
| `GEMINI_API_KEY` | مفتاح Gemini السري |
| `GROQ_API_KEY` | مفتاح Groq السري |
| `SUPABASE_URL` | رابط مشروع Supabase |
| `SUPABASE_PUBLISHABLE_KEY` | Publishable key من Supabase |
| `SUPABASE_SECRET_KEY` | Secret key من Supabase |
| `AI_PROVIDER_ORDER` | `gemini,groq` |
| `AI_DAILY_MESSAGE_LIMIT` | `10` |
| `AI_CHAT_ENABLED` | `true` بعد اكتمال الإعداد فقط |

متغيرات اختيارية لها قيم افتراضية:

- `GEMINI_MODEL=gemini-3.8-flash`
- `GROQ_MODEL=openai/gpt-oss-20b`
- `AI_MAX_OUTPUT_TOKENS=800`
- `AI_PROVIDER_TIMEOUT_MS=18000`

**مهم جدًا:** مفاتيح Gemini وGroq وSupabase Secret توضع في Vercel فقط، ولا تُكتب في `index.html` أو GitHub. المفتاح `SUPABASE_PUBLISHABLE_KEY` مخصص للواجهة ويمكن إظهاره، أما `SUPABASE_SECRET_KEY` فيمتلك صلاحيات عالية ويظل في الخادم فقط. استخدم Environment Variables في Vercel؛ GitHub Secrets مخصصة لخطوات GitHub Actions ولا تُحقن تلقائيًا في تشغيل Vercel.

بعد إضافة المتغيرات، أعد Deploy للمشروع. لا تفعّل `AI_CHAT_ENABLED=true` إلا بعد تشغيل SQL والتأكد من أن متغيرات Supabase ومفتاح مزود واحد على الأقل صحيحة.

## كيف يعمل الشات

1. المستخدم ينشئ حسابًا أو يسجل الدخول من تبويب «مستشار AI».
2. الواجهة ترسل Access Token إلى `/api/ai-chat`؛ الخادم يتحقق منه عن طريق Supabase Auth.
3. الخادم يحجز رسالة واحدة ذريًا من حصة الحساب اليومية بتوقيت القاهرة.
4. يبدأ بـGemini، ثم ينتقل إلى Groq عند فشل المزود الأساسي.
5. في حالة فشل المزودين، يحاول الخادم إرجاع الرسالة إلى عداد اليوم. عند النجاح، يظهر الرد داخل نفس الشات.

سجل المحادثة مؤقت داخل الصفحة ولا يُحفظ في قاعدة البيانات. التجميعة الحالية تُرسل في كل طلب كسياق محدث. الرسائل والسياق يمران عبر مزود AI المختار لمعالجة الطلب وفق شروط وسياسة بيانات ذلك المزود.

## حدود الأمان الحالية

- الحصة اليومية لكل حساب محفوظة في قاعدة البيانات، وليست عدادًا في `localStorage`.
- الحصة الافتراضية 10 رسائل لكل حساب كل يوم بتوقيت القاهرة. تقدر تعدلها من `AI_DAILY_MESSAGE_LIMIT` حتى 50.
- نظام الحصة لا يمنع إنشاء حسابات متعددة. عند فتح الخدمة لعدد أكبر من المستخدمين، أضف حماية من الحسابات الآلية وتقييدًا إضافيًا على مستوى عنوان IP/الاشتراك.
- لا يوجد تحقق من ملكية رقم الهاتف، ولا ينبغي اعتبار حساب البريد الإلكتروني إثبات هوية.
- لا تُرسل كلمات مرور أو بيانات خاصة أو أسرار إلى مستشار AI.
- إذا استنفد المزودان حصتيهما أو غيّرا سياساتهما، قد يتوقف المستشار مؤقتًا؛ لا توجد ضمانة باستمرار المجاني.

## الاختبار والنشر

المشروع يستخدم Node.js 22 وواجهات Vercel Serverless ولا يحتاج خطوة build. من جذر المشروع:

```bash
npm install
npm test
```

ارفع محتويات المجلد إلى جذر مستودع GitHub، ثم اربط المستودع بمشروع Vercel. لا يكفي رفع `index.html` وحده؛ يجب نشر مجلد `api/` و`lib/` و`supabase/` معه.

## الملفات المهمة

- `index.html`: واجهة البحث والتجميعة والشات وتسجيل الدخول.
- `api/search.js`: البحث في مؤشر الأسعار.
- `api/verify.js`: فحص صفحات عروض المتاجر.
- `api/ai-config.js`: يرسل إعدادات Supabase العامة اللازمة للواجهة فقط، دون أسرار AI.
- `api/ai-chat.js`: يتحقق من الحساب والحصة ويشغّل مزودي AI.
- `lib/ai.js`: تجهيز الرسائل وسياق التجميعة والتحويل بين Gemini وGroq.
- `supabase/buildlab-ai-quota.sql`: جدول الحصة والدوال الذرية.
- `lib/shared.js`: تحليل مصدر الأسعار وتصنيف القطع.

## الخصوصية وبيانات الموقع

اختيارات التجميعة والميزانية محفوظة محليًا في متصفح المستخدم. تسجيل الدخول مطلوب للمستشار فقط. البحث يطلب بيانات مؤشر المقارنة من الخادم، وفحص العروض يزور صفحات المتاجر المدعومة عند طلب المستخدم. أسعار المصدر ومؤشرات المخزون ليست ضمانًا للسعر النهائي أو التوفر.
